# RECOMMANDATIONS

## 1. **Priorité Haute** : Utiliser un Modèle avec Tool Calling Natif

**Analyse approfondie (2026-01-30)**: Le problème n'est PAS Maestro mais le modèle.

`deepseek-coder-1.3b-instruct` BASE n'a **pas été entraîné pour le function calling**.

**Solutions** : Modifier la config du block agent pour utiliser un modèle avec tool-use.

| Modèle | Capacités | Notes |
|--------|-----------|-------|
| `HuggingFaceTB/SmolLM2-1.7B-Instruct` | tool-use | **Recommandé** - Même taille que deepseek |
| `HuggingFaceTB/SmolLM2-360M-Instruct` | tool-use | Ultra léger pour tests rapides |
| `NousResearch/Hermes-3-Llama-3.1-8B` | tool-use, function-calling | Excellent, peut nécessiter INT4 |
| `meetkai/functionary-small-v3.2` | function-calling (spécialisé) | Optimisé pour tools |

**Pour tester** :

1. Modifier le fichier `simple-task-executor.agent.block.json` :
```json
{
  "config": {
    "model": "HuggingFaceTB/SmolLM2-1.7B-Instruct"
  }
}
```

2. Re-exécuter le test :
```bash
node C:\Meastro\tools\maestro-cli\index.js run simple-task-executor \
  --input task="List the files" --input workingDir="C:/Meastro"
```

Le LLM-Provider chargera automatiquement le nouveau modèle lors de l'exécution.

## 2. **Priorité Moyenne** : Ajouter la commande `metrics training-run` au CLI

## 3. **Priorité Basse** : Mettre à jour le template de test avec les commandes CLI correctes
