# CONCLUSIONS MAJEURES

## ✅ Victoire : SmolLM2 PEUT faire du Tool Calling!

Contrairement à `deepseek-coder-1.3b-instruct` qui ne pouvait **jamais** produire de JSON structuré pour les tool calls, `SmolLM2-1.7B-Instruct` :

1. **Produit le format JSON correct** : `{"tool":"list_files","args":{"path":"..."}}`
2. **Le tool est détecté et exécuté** par l'AgentBlockExecutor
3. **Les résultats sont retournés** correctement

**Ceci prouve que le problème des runs précédentes était le modèle, pas Maestro.**

## ⚠️ Problèmes Restants

| Problème | Description | Sévérité |
|----------|-------------|----------|
| Inconsistance | Le modèle ne suit pas toujours le format exact | Moyenne |
| Boucles | Parfois appelle le même tool en boucle | Moyenne |
| VRAM | Avec 2 modèles chargés, parfois timeout | Mineure |

## Recommandations

### 1. **Priorité Haute** : Améliorer le System Prompt

Le prompt actuel est trop minimal. Un prompt plus structuré avec :
- Exemples explicites de flux complet (call → result → done)
- Instructions claires sur quand appeler `done`
- Interdiction de répéter les mêmes appels

### 2. **Priorité Moyenne** : Tester d'autres modèles tool-capable

| Modèle | Pourquoi |
|--------|----------|
| `meetkai/functionary-small-v3.2` | Spécialisé function calling |
| `NousResearch/Hermes-3-Llama-3.1-8B` | Excellent pour tools (INT4 requis) |

### 3. **Priorité Basse** : Gestion VRAM

Implémenter un flag pour forcer le déchargement des autres modèles avant de charger un nouveau.
