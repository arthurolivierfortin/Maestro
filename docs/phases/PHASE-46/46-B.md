## Ce que cette sous-phase fait

1. **Creer `tests/SessionManager.test.ts`** avec les categories de tests suivantes :

   **Construction et configuration** :
   - Constructeur avec toutes les options (apiClient, repoPath, template, entryPoint, importSessionTemplate)
   - Constructeur avec valeurs par defaut (template = 'maestro-assistant', entryPoint = 'message', importTemplate = noop)
   - `getSessionId()` retourne `null` avant `ensureSession`
   - `getRepoPath()` retourne le chemin fourni

   **Cycle de vie session (ensureSession via submitTask)** :
   - Cree une session, importe le template, demarre la session au premier message
   - Idempotent : ne recree pas la session au deuxieme message (sessionReady = true)
   - Reutilise une session existante si `.maestro/session.json` existe et le backend la confirme
   - Cree une nouvelle session si `.maestro/session.json` pointe vers une session inexistante sur le backend
   - Gere l'erreur de `createSession` gracieusement (affiche erreur, setBusy(false))
   - Gere l'erreur de `importTemplate` gracieusement

   **submitTask** :
   - Appelle `ensureSession`, puis invoque l'entry point avec les bons inputs (message + repoPath)
   - Demarre le polling apres invocation reussie
   - Gere l'erreur d'invocation (affiche erreur, setBusy(false))

   **Polling (startPolling via fake timers)** :
   - Detecte la completion (noeuds completed + status idle)
   - Detecte les erreurs de session (status error/failed)
   - Detecte l'arbre vide apres 30s (EMPTY_TREE_TIMEOUT_MS)
   - Extrait l'output agent depuis les noeuds et variables
   - Parse le JSON `{"summary":"..."}` de step-complete

   **sendMessage** :
   - Envoie le message comme variable + re-invoque l'entry point

   **cancelTask** :
   - Arrete le polling et setBusy(false)

2. **Deplacer les 4 tests existants** de `App.test.ts` (describe('SessionManager'), lignes 241-401) vers `SessionManager.test.ts`

3. **Ajouter `SessionManager.test.ts` au script `test:fast`** dans package.json

## Patterns de test

**Mock API client minimal** (ne pas reimplementer IApiClient complet) :
```typescript
const mockClient = {
  createSession: vi.fn().mockResolvedValue({ id: 'sess-1234-5678-abcd-ef0123456789' }),
  startSession: vi.fn().mockResolvedValue({}),
  getSession: vi.fn().mockResolvedValue({
    status: 'idle',
    variables: { _executionTree: [], _executionLog: [] },
  }),
  _fetch: vi.fn().mockResolvedValue({ status: 'running' }),
};
```

**Mock filesystem** (pour `.maestro/session.json`) :
```typescript
vi.mock('fs/promises', () => ({
  readFile: vi.fn().mockRejectedValue({ code: 'ENOENT' }),
  writeFile: vi.fn().mockResolvedValue(undefined),
  mkdir: vi.fn().mockResolvedValue(undefined),
}));
```

**Fake timers pour polling** :
```typescript
vi.useFakeTimers();
await sm.submitTask('task', addLine, setBusy);
await vi.advanceTimersByTimeAsync(2100); // premier poll
vi.useRealTimers();
```

## Anti-patterns

- Ne PAS tester les methodes privees directement — tester via `submitTask`, `sendMessage`, `cancelTask`
- Ne PAS utiliser de vrais timers pour le polling — `vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()`
- Ne PAS creer de fichiers `.maestro/session.json` reels — mocker `fs/promises`
- Ne PAS dupliquer les tests existants de App.test.ts — les deplacer proprement
