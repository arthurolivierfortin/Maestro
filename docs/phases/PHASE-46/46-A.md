# 46-A : Corriger le bug critique `importSessionTemplate`

**Effort estime** : 1h

---

## Lecture obligatoire

- `packages/maestro-code/App.ts` lignes 184-193 — props du composant App (manque `importSessionTemplate`, `template`, `entryPoint`)
- `packages/maestro-code/App.ts` lignes 214-241 — `handleProviderSetupComplete` cree un SessionManager sans `importSessionTemplate`
- `packages/maestro-code/App.ts` lignes 800-825 — `startInteractive` passe `options` complet au SM initial (ligne 808) mais pas au composant App (ligne 820-825)
- `packages/maestro-code/services/SessionManager.ts` lignes 71-77 — constructeur avec `importSessionTemplate || (async () => {})`
- `packages/maestro-cli/cli.ts` lignes 6344-6368 — le CLI passe `importSessionTemplate` dans les options

## Le bug

Quand l'utilisateur passe par le flux provider-setup (premier lancement), `handleProviderSetupComplete` (ligne 230) cree un nouveau SessionManager :

```typescript
setLiveSessionManager(new SessionManager({ apiClient: newClient, repoPath }));
```

Il manque `importSessionTemplate`, `template`, et `entryPoint`. Le constructeur de SessionManager utilise `options.importSessionTemplate || (async () => {})` — donc `importTemplate` devient un no-op. Le template n'est jamais importe, les entry points ne sont jamais enregistres, et le premier message echoue avec "Entry point 'message' not found".

---

## Ce que cette sous-phase fait

1. **Ajouter les props manquantes au composant App** (ligne 184) : `importSessionTemplate`, `template`, `entryPoint`

2. **Passer ces props depuis `startInteractive`** (ligne 820-825) : extraire `importSessionTemplate`, `template`, `entryPoint` de `options` et les transmettre au composant App

3. **Utiliser ces props dans `handleProviderSetupComplete`** (ligne 230) : passer `importSessionTemplate`, `template`, `entryPoint` et `repoPath` au nouveau SessionManager
