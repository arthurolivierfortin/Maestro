## Ce que cette sous-phase fait

### 1. Consolider les messages systeme

**Avant** (5 lignes dans le conversation log pour chaque message) :
```
19:55:27 Creating session...
19:55:27 Session: 04079e75
19:55:27 Importing template: maestro-assistant
19:55:27 Session started
19:55:27 Invoking: message
```

**Apres** (2 lignes) :
```
19:55:27 Starting session...
19:55:27 Session ready (04079e75)
```

Les messages detailles ("Importing template", "Session started") sont gardes uniquement si `process.env.MAESTRO_DEBUG` est defini.

### 2. Ameliorer les messages d'erreur

Remplacer les messages techniques par des messages actionables :

| Avant | Apres |
|-------|-------|
| `Error: Entry point 'message' not found` | `Could not start conversation — the assistant workflow is not configured. Try restarting with 'maestro code'.` |
| `Error: Agent did not respond — execution tree is empty.` | `The agent didn't respond. Check that your LLM provider is running. Try '/status' to check.` |
| `Error: ${err.message}` (brut) | `Could not create session: [detail]. Try '/status' to check connection.` |
| `Error: Session timed out (5 min)` | `The agent took too long to respond (5 min timeout). Try a simpler task or check '/status'.` |

### 3. Corriger le placeholder de l'input desactive

**Avant** : quand `disabled === true` (agent en cours), le placeholder est encore `"Send a message to the agent..."` — trompeur car l'input est desactive.

**Apres** : quand `disabled === true`, le placeholder devient `"Agent is working..."`.

Implementation dans `TaskInputBar.ts` : ajouter une prop `busyPlaceholder` ou simplement changer le placeholder par defaut quand `disabled`.

### 4. Allonger la duree de l'etat error

**Avant** : 3 secondes pour `completed` ET `error`, puis retour a `idle`.

**Apres** :
- `completed` : 3 secondes (inchange)
- `error` : 10 secondes — les erreurs meritent plus de visibilite

### 5. Message de bienvenue contextuel

**Premier lancement** (pas de `.maestro/session.json`) :
```
Welcome to Maestro Code. Press / to type a task.
```

**Session restauree** :
```
Previous session restored. Press / to continue.
```

### 6. Mettre a jour les tests

Les tests existants (`App.test.ts`, `SessionManager.test.ts`) referent aux textes exacts des messages. Mettre a jour les assertions pour les nouveaux textes.

## Anti-patterns

- Ne PAS traduire les messages en francais — garder l'interface en anglais (les utilisateurs cibles sont globaux)
- Ne PAS supprimer les messages systeme completement — les consolider. Un utilisateur veut savoir que la session est prete, pas les 4 etapes de preparation
- Ne PAS changer la logique du polling ou de la soumission — uniquement les messages affiches
- Ne PAS casser les tests existants en changeant les messages sans mettre a jour les assertions
