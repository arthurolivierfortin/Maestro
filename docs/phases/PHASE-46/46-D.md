### Strategie par fichier

Pour chaque fichier :
1. Retirer `// @ts-nocheck`
2. Lancer `npx tsc --noEmit` (ne regarder que les erreurs de CE fichier)
3. Corriger les erreurs (ajouter types aux params, props, remplacer `any` implicites)
4. Relancer `npm run test:fast` pour verifier aucune regression

## Anti-patterns

- Ne PAS utiliser `any` comme solution de facilite — utiliser `unknown` + cast explicite quand le type n'est pas connu
- Ne PAS retirer @ts-nocheck de TOUS les fichiers avant de corriger les erreurs — un par un, tester a chaque fois
- Ne PAS changer la logique des composants — le seul changement autorise est l'ajout de types et d'interfaces
- Ne PAS refactoriser la structure des composants "parce que les types revelent un probleme d'architecture" — noter le probleme dans le checkpoint et continuer
