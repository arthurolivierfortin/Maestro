## ERREURS INTERDITES

> **Lire AVANT de coder. Violation = revert immediat.**

1. **NE JAMAIS mettre de tool dispatch, response parsing, ou agentic loop dans AgentBlockExecutor.** Cette erreur a ete faite 3+ fois. `AgentBlockExecutor` fait UNIQUEMENT : (a) conversation setup dans `PrepareExecutionAsync`, (b) extraction `_agentResult` dans `ExtractResultAsync`. TOUT le reste est dans `config.nodes`.

2. **NE JAMAIS mettre de if-chain dans ToolBlockExecutor.** C'est exactement le god class qu'on vient de detruire. Chaque tool a ses propres `config.nodes`. `ToolBlockExecutor` mappe les inputs/outputs depuis le schema du block.json, execute les nodes via la base class, et c'est tout.

3. **NE PAS hardcoder de default pour config.nodes.** Si un block n'a pas de `config.nodes`, le fallback temporaire (53-D) gere ca. Pas de default permanent.

4. **NE PAS casser le I/O contract.** Agent = meme I/O que inference (prompt→text). Workflow = I/O arbitraire. Tool = I/O defini par block.json schema. Ne pas ajouter d'outputs supplementaires.

5. **NE PAS dupliquer le moteur de nodes.** `MultiNodeBlockExecutor.ExecuteNodesAsync()` delegue a `NodeExecutionEngine`. Un seul endroit pour executer des nodes.

## Principe fondamental

> **Agent, workflow et tool ont le meme interne.** Ils sont tous composes de blocks a l'interieur. Un agent n'a pas de logique de boucle en C# — si un agent a besoin d'une boucle, c'est un node `while` dans ses `config.nodes`. Meme chose pour les tools.
>
> **La logique existante en C# est la REFERENCE.** Les blocks reproduisent exactement la meme logique que le code C# faisait avant. C'est ce qui permettra plus tard de "compiler" (compresser les blocks en code natif pour zero overhead).

## 2. `WorkflowBlockExecutor` extends `MultiNodeBlockExecutor`

```csharp
public class WorkflowBlockExecutor : MultiNodeBlockExecutor
{
    public override string SupportedType => "workflow";

    protected override Task<Dictionary<string, object>> PrepareExecutionAsync(...)
    {
        // Pass-through : les inputs sont directement les variables
        return Task.FromResult(inputs);
    }

    protected override Task<BlockExecutionResult> ExtractResultAsync(...)
    {
        // Retourne toutes les variables de session comme outputs
        return Task.FromResult(new BlockExecutionResult
        {
            Success = true,
            Outputs = context.GetAllVariables()
        });
    }
}
```

**Migration** : Le chemin inline dans l'ancien `EntryPointExecutor` (lignes 1933-1984) qui gerait `blockType: "workflow"` est remplace par cette classe. `NodeExecutionEngine` dispatch maintenant les workflows vers `WorkflowBlockExecutor` via `BlockExecutorRegistry`.

## 3. `AgentBlockExecutor` extends `MultiNodeBlockExecutor`

```csharp
public class AgentBlockExecutor : MultiNodeBlockExecutor
{
    public override string SupportedType => "agent";

    protected override async Task<Dictionary<string, object>> PrepareExecutionAsync(...)
    {
        // 1. Creer ou recuperer la conversation
        var conversationId = $"{context.Variables["sessionId"]}:{block.Id}";
        await _conversationManager.CreateOrGetConversation(conversationId, ...);

        // 2. Ajouter le prompt user a la conversation
        if (inputs.TryGetValue("prompt", out var prompt))
            await _conversationManager.AddMessage(conversationId, "user", prompt.ToString());

        // 3. Injecter les variables pour les nodes
        inputs["_conversationId"] = conversationId;
        inputs["maxIterations"] = block.Config.GetValueOrDefault("maxIterations", 25);
        return inputs;
    }

    protected override Task<BlockExecutionResult> ExtractResultAsync(...)
    {
        // Meme I/O qu'un inference block : prompt/messages → text
        var agentResult = context.Variables.GetValueOrDefault("_agentResult", "");
        return Task.FromResult(new BlockExecutionResult
        {
            Success = true,
            Outputs = new Dictionary<string, object>
            {
                ["content"] = agentResult,
                ["_agentResult"] = agentResult
            }
        });
    }
}
```

**20-30 lignes de code metier.** Tout le reste (boucle, parsing, dispatch) est dans `config.nodes`.

## 4. `ToolBlockExecutor` extends `MultiNodeBlockExecutor`

```csharp
public class ToolBlockExecutor : MultiNodeBlockExecutor
{
    public override string SupportedType => "tool";

    protected override Task<Dictionary<string, object>> PrepareExecutionAsync(...)
    {
        // Mapper les inputs depuis le schema du block.json
        // Les inputs arrivent deja resolus par le NodeExecutionEngine
        return Task.FromResult(inputs);
    }

    protected override Task<BlockExecutionResult> ExtractResultAsync(...)
    {
        // Mapper les outputs depuis le schema du block.json
        var outputs = new Dictionary<string, object>();
        foreach (var outputDef in block.Outputs)
        {
            if (context.Variables.TryGetValue(outputDef.Name, out var value))
                outputs[outputDef.Name] = value;
        }
        return Task.FromResult(new BlockExecutionResult
        {
            Success = true,
            Outputs = outputs
        });
    }
}
```

**Un tool atomique** (`file-write`) a 1 node dans config.nodes.
**Un tool composite** (`create-commit`) a N nodes (read diff, build prompt, LLM call, git commit).
Meme executor, meme moteur.
