## Couche 5 — Agents E2E (le coeur de la verification)

Chaque agent critique doit etre invoque dans une vraie session et produire un resultat correct.

### 5.1 — maestro-assistant (message simple)

```bash
node index.js session create --type project --name "E2E Verify - Assistant" \
  --template maestro-assistant --start
node index.js session invoke <session-id> message --input prompt="What is Maestro?"
```

**Criteres** :
- [ ] L'agent repond de maniere coherente
- [ ] La conversation contient le message user + la reponse assistant
- [ ] `_executionTree` montre les nodes (conversation-read, llm-call, response-parser, etc.)
- [ ] Pas d'erreur dans `_executionLog`

### 5.2 — maestro-assistant avec tool calling

```bash
node index.js session invoke <session-id> message \
  --input prompt="List all available blocks in the system"
```

**Criteres** :
- [ ] Tool call detecte par response-parser (type = "tool-call")
- [ ] tool-dispatcher execute le tool correctement
- [ ] Resultat du tool ajoute a la conversation via conversation-append
- [ ] L'agent continue la boucle apres le tool call
- [ ] L'agent fait step-complete avec un resume

### 5.3 — maestro-assistant multi-tour (memoire)

```bash
node index.js session invoke <session-id> message --input prompt="Hello, my name is Arthur"
node index.js session invoke <session-id> message --input prompt="What is my name?"
```

**Criteres** :
- [ ] Memoire de contexte fonctionne (conversation persistee entre invocations)
- [ ] conversation-read retourne l'historique complet
- [ ] L'agent utilise le contexte pour repondre correctement
