### Étape 4 : `ClaudeCodeLLMProvider` — `--resume` (le plus complexe)

**Fichier** : `llm-provider/dotnet/src/LLMProvider.ClaudeCodeProvider/ClaudeCodeLLMProvider.cs`

Remplacer l'approche `[user]/[assistant]` markers par le vrai multi-turn via `--resume`.

**4a. Nouvel état interne** :
```csharp
private sealed class ConversationState
{
    public string CliSessionId { get; set; } = "";
    public int SentMessageCount { get; set; }
    public DateTime LastUsed { get; set; } = DateTime.UtcNow;
}

private readonly ConcurrentDictionary<string, ConversationState> _sessions = new();
```

**4b. `CompleteAsync` modifié** :

Le `ConversationId` arrive via `request.ConversationId` (champ existant de type `ConversationId?`).
Chemin complet : `Maestro.LLMRequest.ConversationId` → `CompleteRequest.ConversationId` (HTTP) → `LLMProvider.LLMRequest.ConversationId` → `provider.CompleteAsync(request, history)`.

- Si `conversationId` est null ou pas dans `_sessions` → premier appel :
  - Extraire le dernier message user de `conversationHistory` (ou utiliser `request.Prompt`)
  - `BuildArguments` SANS `--no-session-persistence`
  - `RunProcessAsync`, capturer stdout
  - Extraire `session_id` du JSON de sortie
  - Stocker dans `_sessions[conversationId.ToString()]`

- Si dans `_sessions` → appel suivant :
  - Calculer les nouveaux messages (`conversationHistory[state.SentMessageCount..]`)
  - Extraire le dernier message user
  - `BuildArguments` avec `--resume <sessionId>`, sans `--no-session-persistence`
  - `RunProcessAsync`
  - Mettre à jour `state.SentMessageCount` et `state.LastUsed`

**4c. Fallback si `--resume` échoue** :
- Retirer la session du cache (`_sessions.TryRemove`)
- Relancer un appel neuf (`-p` avec tout le contexte formaté en markers `[user]/[assistant]`)
- Logger un warning

**4d. `ParseResponse` modifié** — extraire `session_id` :
```csharp
var sessionId = root.TryGetProperty("session_id", out var sid) ? sid.GetString() : null;
```
Retourner via un nouveau paramètre `out string? sessionId` ou via le type de retour.

**4e. `BuildArguments` modifié** :
- Retirer `"--no-session-persistence"` des arguments par défaut
- Ajouter un paramètre `resumeSessionId` optionnel :
  ```csharp
  if (!string.IsNullOrEmpty(resumeSessionId))
  {
      args.Add("--resume");
      args.Add(resumeSessionId);
  }
  ```

**4f. Nettoyage** :
- `CleanupConversation(string conversationId)` — supprime de `_sessions`
- Timer avec `System.Threading.Timer` qui purge les entrées `LastUsed > 1h` toutes les 10 min
- `--max-turns` reste à 1, `--tools ""` reste

### Étape 7 : Fix #5 — Phases mises à jour dans les nœuds imbriqués

**Fichier** : `apps/backend/src/Maestro.Infrastructure/Sessions/EntryPointExecutor.cs`

Dans `ExecuteForEachNodeAsync`, avant l'exécution de chaque item, si l'item a un `phaseId` :

Après l'exécution :
