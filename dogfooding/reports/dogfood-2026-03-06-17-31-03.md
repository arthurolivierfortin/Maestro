### Real Mode (Phase 2)

**Startup:** Connected to live backend (5000) and LLM-Provider (5010). Real latency visible (4-64ms). 156 blocks discovered, 17 models, 146+ sessions from previous runs.

**Catalog — The Rendering Problem:**
With 156 real blocks, the catalog's row layout breaks badly. Blocks with long IDs (system:documentation-generator), many tags (conversation,tool-calling,structured-output), or long type names (conversation-append) overflow the terminal width and wrap to the next line. This breaks:
- Column alignment (ID/fitness/tags shift)
- Type badge truncation ([agent → [agen with ] on next line)
- Selection indicator visibility (→ disappears on wrapped rows)
- Consistent row height (some 1 line, some 2-3 lines, with blank lines between)

Affected blocks: Documentation Agent, Experiment Manager, Maestro Assistant, Publisher Agent, Research Agent, Block Validation Workflow, code-analyzer, context-builder. At least 33% of visible rows in filtered agent view.

**Fix needed:** Cap each column width and truncate with "..." — prioritize type badge (always complete), name (most important), fitness, then truncate ID/tags/description aggressively.

**Catalog — Missing Search:**
With 156 blocks, finding a specific block by scrolling is painful. I had to press down ~16 times to reach "Maestro Assistant" from the top. The type filter [1-4] helps (narrowed to 44 agents) but there's no text search. A "/" search or type-ahead filter is essential at this scale.

**Contract Test [T] — Working!**
The standout feature. When selecting a block with a contract, [T] appears in the help bar, pressing it:
1. Auto-expands the block row
2. Shows "Testing {block} against {contract}..." in yellow
3. After ~5s, displays full results inline:
   - Contract name and version
   - Tests passed/total, cost, duration
   - Per-feature breakdown with tree chars and progress bars
   - Performance, Composability, Cost Factor metrics

Minor issues: (1) tree branch chars reused for both features and aggregate metrics (misleading hierarchy), (2) expanded row has rendering artifact on version line ("version: 1.0.0tioatomic: no as the full assistant." — text concatenation bug).

**Agent — End-to-End Works, Persistence Broken:**
First message: Session created, full workflow executed, agent responded contextually (recognized Cantante as Node.js/TS/Electron project). Response was in French despite English input — prompt/locale issue.

Second message: Asked "Please respond in English. What blocks are available?" — got IDENTICAL French introduction response. This is a critical bug: either conversation history isn't being loaded into the LLM context, or the persistent conversation mechanism is broken. The workflow shows "Load History ✓" but the history clearly isn't influencing the response.

**Models — Duplicate Names:**
17 models loaded but many are indistinguishable: "Claude haiku" appears 4 times, "Claude sonnet" 3 times, "Claude opus" 3 times. No version numbers or model IDs shown. User cannot tell claude-haiku-4-5 from claude-3-haiku. The model list needs to show model IDs or version qualifiers.
