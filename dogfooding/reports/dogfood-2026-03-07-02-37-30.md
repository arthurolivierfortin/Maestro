## Bugs Found and Fixed

### Bug 1: DI Crash — Dictionary Null Key (CRITICAL)
**Root cause**: `NodeExecutionEngine` constructor stored `INodeHandler` instances in `Dictionary<string?, INodeHandler>` using `handler.NodeType` as key. `BlockRefHandler.NodeType` returns `null`, which caused `System.ArgumentNullException` at runtime despite nullable annotation.

**Impact**: ALL workflow invocations silently failed after backend startup. `Task.Run` in `EntryPointExecutor` swallowed the exception — no log output, no session error state.

**Fix**: Separated null-key handler into dedicated `_blockRefHandler` field instead of dictionary storage.

**File**: `Maestro.Infrastructure/Sessions/NodeExecutionEngine.cs`

### Bug 2: Conversation Persistence Loss (MAJOR)
**Root cause**: `InMemoryConversationManager` loses all data on process restart. `maestro-assistant-workflow` checks `_activeConversation != ""` (ensure-conversation) but doesn't verify the conversation actually exists in memory.

**Impact**: After any backend restart, `save-user-message` fails with "Conversation 'xxx' not found", breaking the entire workflow sequence.

**Fix**: `ConversationBlockExecutor` now auto-recreates missing conversations in `ExecuteAddMessage` and `ExecuteGetMessages`. Added `CreateConversation(string?, string)` overload to `IConversationManager`.

**Files**: `ConversationBlockExecutor.cs`, `IConversationManager.cs`, `InMemoryConversationManager.cs`

### Bug 3: French Language Responses (SYMPTOM)
**Root cause**: Not a separate bug — stale `C:\Cantante\.maestro\session.json` pointed to old session with corrupted French conversation history. With conversation persistence fixed + fresh session, agent correctly matches user's language.

**Fix**: Deleted stale session.json to force fresh session creation.
